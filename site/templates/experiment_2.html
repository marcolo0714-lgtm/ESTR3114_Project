Experiment 2 · CIFAR-100 multitask classification

Can gradient surgery help twenty tasks share a CNN?

Ordinary joint training and PCGrad, using identical inputs, initialization, model architecture and optimizer settings.

Completed comparison · Seed 42 only · 10,000 steps · Validation results

Main finding. At the final step, PCGrad reaches 69.12% validation accuracy versus 67.12% for joint training, a {{ report.gain }} percentage-point gain. It improves 18 of 20 tasks but takes {{ report.runtime_ratio }} times as long in the recorded implementation.
Scope of the evidence. These are conditional five-class validation results from one seed. The held-out test set has not been evaluated. No variability across seeds or statistical significance is claimed.

What are the twenty tasks?

CIFAR-100 contains 100 fine classes grouped into twenty superclasses. Each superclass becomes a separate five-class task. An image in the fish task must be classified as one of the five fish classes.

The correct superclass is supplied. The model uses the corresponding private classification head. This is not ordinary 100-class recognition, and the model does not infer which superclass an uploaded image belongs to. Random uniform guessing within a task gives 20% expected accuracy.

The CNN learns a common representation for all tasks. Each task has a separate final classifier; its labels and head are never mixed with those of another task. The training split contains 2,250 images per task, validation 250, and test 500.

Two training methods

Let Lt be the mean cross-entropy loss on task t's eight images. Let gt be its gradient with respect to the shared CNN parameters. All task weights are wt = 1/20.

MethodShared update directionMeaning
Jointg = (g1 + … + g20) / 20Differentiate the equally weighted sum of task losses. Conflicting components can cancel.
PCGradg = (h1 + … + h20) / 20Modify conflicting shared gradients, then combine them using the same weights.

PCGrad projection

For each task i, initialize hi = gi. Visit the other nineteen tasks in a random order. When the current hi has a negative dot product with the original peer gradient gj, apply:

hi ← hi − hi · gj‖gj‖² gj

This removes the component opposing that peer. Nonconflicting components are left unchanged. A later projection may reintroduce conflict with an earlier peer, so final pairwise cosines need not all be nonnegative. The implementation uses a Gram matrix to perform the sequential projections.

Only the shared gradients are projected. Each private head retains its ordinary task gradient weighted by 1/20. The resulting gradients are passed to the same SGD optimizer with momentum and weight decay.

A 2D example with three gradients

Use three tasks with gA = (2, 0), gB = (−1, 1), and gC = (−2, 1). Give each task weight 1/3. This example illustrates the calculation; it is not a recorded training step.

First compute all three original gradients and keep them fixed. Make separate working copies hA, hB, hC. For this illustration, choose peer orders B then C for A, A then C for B, and A then B for C. Real PCGrad shuffles each task's peers.

Then combine the completed working gradients:

gPCGrad = [(3/5, 6/5) + (0, 1) + (0, 1)] / 3 = (1/5, 16/15).

Ordinary joint training would use [(2, 0) + (−1, 1) + (−2, 1)] / 3 = (−1/3, 2/3).

Why does peer order matter?

If A visits C first, it becomes (2/5, 4/5). Its dot product with original B is then 2/5 ≥ 0, so it stays there. Reversing the other peer orders still leaves hB = hC = (0, 1). The final average becomes (2/15, 14/15), different from (1/5, 16/15).

It is the peer order within each working gradient that matters. Merely processing A before B or B before A does not change the result when their peer lists are fixed: every projection uses original peers, never another task's already projected h. The twenty-task experiment follows the same sequence with weight 1/20.

What the metrics mean

MetricDefinition and interpretation
Accuracy ↑Correct predictions divided by images, computed within each task and then averaged equally across twenty tasks. Every validation task has the same number of images.
Macro-F1 ↑For each class, F1 = 2TP / (2TP + FP + FN). Average the five class F1 scores within each task, then average across tasks. Undefined scores use zero.
Cross-entropy ↓Mean negative log probability assigned to the correct class, averaged across tasks. It considers probability quality, not only which class ranks first.
Worst-task accuracy ↑The lowest accuracy among the twenty tasks. This checks whether gains in the average also benefit the weakest task.

Percentages below are scores. A difference between two percentage scores is measured in percentage points. One training seed cannot supply a sample standard deviation across seeds.

Recorded total time includes training, validation, logging and checkpoint writing, excluding asset loading. PCGrad costs {{ report.runtime_ratio }} times the total time and approximately 10.49 times training-only time. This is the measured cost of this implementation and workload, not a fixed overhead for PCGrad.

Joint usually obtains its combined gradient in one backward pass. PCGrad extracts twenty task gradients separately and checks nineteen peers for each task. In this implementation, task gradients traverse the shared graph for a combined 160-image batch, which creates repeated computation.

At roughly the time joint finishes (9.54 minutes, 67.12% accuracy), PCGrad's most recent validation check is at step 1,000 (47.26%, recorded at about 9.21 minutes before its evaluation). This is a descriptive time comparison under these schedules, not a separately tuned fixed-time benchmark. PCGrad is stronger per update, but joint reaches useful accuracy much sooner.

PCGrad greatly reduces sampled conflict, but this alone does not prove the cause of its accuracy gain. Projection changes gradient direction and magnitude, and both methods follow different parameter trajectories. Equal learning rates do not imply equal update norms.

What the results support

  • A persistent validation advantage. PCGrad leads at every recorded evaluation and gains 2.00 final accuracy points. At step 6,000, it reaches 67.14%, approximately joint's final accuracy after 10,000 updates.
  • Broad, but not universal, task gains. Eighteen final task accuracies improve. At the separately selected best checkpoints, seventeen improve, one ties and two worsen.
  • Diminishing late returns. The best-accuracy steps are 9,500 for joint and 9,200 for PCGrad. PCGrad's lowest validation cross-entropy occurs earlier, at 6,100; its loss then rises slightly even while accuracy can improve.
  • A substantial compute trade-off. Better accuracy at equal updates does not imply better performance at equal elapsed time.
  • One seed, validation only. This completed study does not establish repeatability across seeds, statistical significance or held-out test performance. No seed SD or test score is reported.
  • Checkpoint selection is visible. The image demo defaults to each method's best-validation checkpoint and also offers the final states. Best-validation scores have been used for selection.
  • An adaptation of the benchmark. This is a shared-CNN comparison, without routing networks or independent-per-task baselines. It is not an exact reproduction of the original PCGrad paper's full evaluation.

The dataset split, class mapping, code/data hashes, summaries and compact monitoring evidence are bundled with this site. Demo predictions use these saved weights; no training is performed by the website.
